## Tooling and evidence disposition

- The qualified enumeration manifest records `manifest`, Cargo target, kind, and the harness listing; its target identity is package/target/test-name based and has no source-path field. The schema-1 parity baseline likewise records test identities and counts rather than source paths. Both checked-in baselines remain unchanged because the target names and 22 function identities are retained.
- `scripts/test_architecture_policy.json` contains reviewed `#[path]` attachments for relocated in-crate unit tests, but no path records for these root integration/performance targets. It therefore needs no BOV-C1 path change.
- CI invokes the affected targets by their unchanged Cargo names. Its commands and feature gates need no path changes.
- The only source-level path fix is the soak target's `#[path = "support.rs"]` declaration. Fixture paths remain rooted at `CARGO_MANIFEST_DIR` or at the unchanged `tests/fixtures/` location.
- Historical BO-M9-C3 identity and acceptance ledgers remain untouched. The 37 dormant root test files were not moved, registered, or activated in this phase.
- The configured Compile is recorded separately in the BOV-C1 authoritative working plan. The formal Test layer and live enumeration parity command were not run by the Implementer in this phase.
